# Задача агента: синхронизировать проекты на сайте

Сайт https://asofwar.github.io/ собирается из `data/projects.json`. Версии и даты релизов
подтягиваются автоматически при каждой сборке, их руками не трогать. Задача агента —
находить новые проекты Asofwar на GitHub, добавлять их на сайт и держать статусы в актуальном виде.

## Жёсткие правила

- Меняешь только `data/projects.json`. Другие файлы не трогаешь.
- Существующие проекты не удаляешь и не переупорядочиваешь. Убирает проекты только владелец.
- Никаких данных из приватных репозиториев: только то, что видно публично.
- Автор и коммитер каждого коммита — `Asofwar <7397608+Asofwar@users.noreply.github.com>`.
  Перед первым коммитом:
  `git config user.name "Asofwar"` и `git config user.email "7397608+Asofwar@users.noreply.github.com"`.
- В коммитах и PR запрещены любые упоминания ИИ: никаких `Co-Authored-By`, `Generated with`,
  `Assisted-by`, слов Claude, Anthropic, AI. Сообщение коммита — одна строка на русском,
  без тела, например `Добавлен проект Foo` или `Обновлены статусы: Foo, Bar`.
- Нет изменений — нет коммита. Просто заверши работу с коротким отчётом.

## Шаги

1. Получи публичные репозитории владельца:
   `curl -s "https://api.github.com/users/Asofwar/repos?per_page=100&type=owner&sort=pushed"`
   (или `gh repo list Asofwar --limit 200 --json name,description,isFork,isArchived,visibility,pushedAt,homepageUrl,primaryLanguage`).
2. Отбери кандидатов:
   - публичный, не архивный, не форк;
   - его нет в `projects[]` (сравни с `source`, `releases` и `link.url`) и нет в `ignore[]`;
   - были push за последние 120 дней.
3. По каждому кандидату прочитай README и описание репо, затем реши:
   - **Настоящий проект автора** (программа, библиотека, мод, инструмент, сервис) — добавь карточку.
   - **Не проект** (конфиги, списки, зеркала, пустые или учебные репо, каналы релизов) — добавь в `ignore[]`
     запись `{ "repo": "Asofwar/<name>", "reason": "<коротко почему>" }`, чтобы не проверять его снова.
4. Новая карточка (добавляй в конец `projects[]`):
   ```json
   {
     "id": "kebab-case, уникальный",
     "title": "Название как в README",
     "kind": "1–3 слова по-русски: «Android-приложение», «Мод для RimWorld», «CLI-утилита»",
     "summary": "1–2 предложения по-русски, до 260 символов: что делает и для кого. По фактам из README, без рекламы",
     "stack": ["языки и ключевые технологии"],
     "platforms": ["где работает"],
     "status": "live | dev | research",
     "releases": "Asofwar/<repo> если есть GitHub Releases, иначе null",
     "link": { "url": "homepage, последний релиз или репо", "label": "Сайт проекта | Скачать | Репозиторий" },
     "source": "https://github.com/Asofwar/<repo>",
     "fork_of": null,
     "added": "YYYY-MM-DD (сегодня)"
   }
   ```
   `status`: `live` — есть стабильный релиз или работающий деплой; `dev` — активная разработка без
   стабильного релиза; `research` — эксперимент или исследование.
5. Существующие карточки: меняй `status` с `dev` на `live` только если у проекта появился первый
   стабильный (не pre-release) релиз. Остальные поля без явной причины не трогай.
6. Проверка: `python3 scripts/build.py` должен завершиться без ошибок. Ошибка — исправь JSON.
7. Публикация:
   - закоммить `data/projects.json` и запушь в `main`;
   - если push в `main` запрещён, создай ветку, открой PR и смёржи его сам:
     `gh pr merge --squash --delete-branch --subject "<та же строка>" --body ""`;
   - проверь автора: `git log -1 --format='%an <%ae> | %cn <%ce>'` — оба должны быть Asofwar.
8. Отчёт: какие проекты добавил, какие отправил в `ignore`, какие статусы поменял.
